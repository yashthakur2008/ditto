# Ditto Portfolio Checklist

Use this checklist to turn Ditto into a stronger LinkedIn, GitHub, and recruiter-facing project.

## Repository story

- [x] README explains the product, stack, architecture, endpoints, privacy posture, and deployment path.
- [x] Portfolio case study explains why the project is more than a prompt demo.
- [x] Scalability roadmap names the reliability, cost, safety, and accessibility gaps before production.
- [x] School accessibility readiness plan frames a fundable first wedge.
- [x] Demo script is available in `DEMO_SCRIPT.md`.
- [x] Tomorrow runbook is available in `TOMORROW_DEMO_READINESS.md`.
- [x] Demo-safe URL and no-secrets checklist is available in `DEMO_SAFE_URLS.md`.
- [x] LinkedIn post draft is available in `LINKEDIN_POST_DRAFT.md`.

## Demo assets to capture

- [ ] 60 to 90 second video following `DEMO_SCRIPT.md`.
- [ ] Screenshot of the landing page.
- [ ] Screenshot of preference setup.
- [ ] Screenshot of chat URL input.
- [ ] Screenshot or GIF of rebuilt output.
- [ ] Screenshot of before/after accessibility score panel.
- [ ] Screenshot of Chrome extension popup.
- [ ] Optional short clip showing batch transform or share link.

## Proof points to include in the post

- [ ] One concrete before/after score movement from a safe demo page.
- [ ] One sentence on privacy: local-first preferences, opt-in history, share links omit profile.
- [ ] One sentence on safety: URL validation, sandboxed output, content classification.
- [ ] One sentence on cost awareness: URL/profile cache and lighter model for scoring/classification.
- [ ] One sentence on distribution: web app plus Chrome MV3 extension.
- [ ] One sentence on startup path: school accessibility office pilot.

## Recruiter-facing bullets

- [ ] Full-stack product surface, not only a model call.
- [ ] Arbitrary URL input through validated scraping.
- [ ] Accessibility personalization across multiple reader profiles.
- [ ] Before/after scoring and report export direction.
- [ ] Chrome extension distribution surface.
- [ ] Clear production roadmap: async jobs, quotas, persistent cache, observability, WCAG validation.

## Before posting publicly

- [ ] Confirm demo URLs are public and safe.
- [ ] Confirm no screenshots expose API keys, private user data, or unpublished school/customer names.
- [ ] If using live providers, verify quota/cost limits first.
- [ ] Replace placeholder deploy URLs in README if production URLs differ.
- [ ] Pin the repo and include a direct demo video link.
